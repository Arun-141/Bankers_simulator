    About the algorithm
    
    
    
      
    What it does
    Proposed by Dijkstra, the Banker's Algorithm grants a resource request only if the system stays in a safe state: one where some order exists that lets every process obtain its maximum claim and finish. Like a bank, it never lends cash it might not be able to recover.
    
      
    Data structures
    For n processes and m resource types: Available[m], Max[n][m], Allocation[n][m] and Need[n][m] = Max − Allocation.
    
      
    Safety algorithm
    1. Set Work = Available, Finish[i] = false. 2. Find an unfinished i with Need[i] ≤ Work. 3. Work += Allocation[i]; Finish[i] = true; repeat. 4. If every Finish[i] is true the state is safe, and the order found is the safe sequence.
    
      
    Resource-request algorithm
    If Request > Need, it is an error. If Request > Available, the process waits. Otherwise pretend to allocate it and run the safety algorithm; grant only if the result is safe, else roll back.
    
      
    Safe vs unsafe
    Safe means deadlock is impossible. Unsafe does not guarantee deadlock, but it means the OS can no longer promise to avoid it, so avoidance refuses to enter such states.
    
      
    OS significance
    It shows the trade-off of deadlock avoidance: it needs advance knowledge of maximum demands and costs O(m·n²) per check, but it avoids killing processes or rolling back work. Real systems rarely use it directly, yet it is the standard model for reasoning about resource ordering and safety.
